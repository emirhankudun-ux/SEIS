# Required Output Contract

Return a Goal report that identifies project, Goal ID and title, status, maturity,
owner, branch, issue and pull request, objective, scope, non-goals, completed work,
changed files, architecture and design decisions, AI and routing notes, tool and
permission notes, security and privacy, accessibility, performance, data and
migration, validation commands and results, failed or skipped checks, evidence,
risks, blockers, rollback, remaining gaps, next recommended Goal, and worktree
status.

Lead with the actual outcome. Distinguish implementation from plan, local from
hosted evidence, generated from authored content, demo from live behavior, and
current facts from dated observations. Include exactly one final repository-state
line: `Repository state: clean`, `Repository state: dirty`, `Repository state:
blocked`, or `Repository state: not verified`.

If work remains safe and in scope, continue rather than presenting a shallow
audit as completion. If new authority or a materially different product choice
is required, stop at the smallest coherent unit and ask for that decision.
