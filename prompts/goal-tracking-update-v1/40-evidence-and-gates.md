# Evidence and Quality Gates

Evidence must be reproducible, relevant, durable, public-safe, and tied to the
claim it supports. Record exact commands and exit status, test or scan reports,
artifact hashes, review records, screenshots, contracts, or GitHub check URLs.
Never write "tests pass" without naming the commands. Mark failed, unavailable,
and skipped checks with reasons; automated output is not automatically correct.

Evaluate every applicable architecture, product, creative, design, UI/UX,
engineering, AI integrity, routing, agent permission, MCP/tool, security,
privacy, accessibility, performance, data, documentation, DevOps, testing,
release, and public-readiness gate. A required failed or blocked gate prevents
completion. A not-applicable gate needs a defensible scope reason rather than
being used to avoid review.

Do not store private chain-of-thought. Record concise decisions, inputs, outputs,
alternatives, limitations, evaluation results, and evidence. Redact sensitive
values; a security finding should identify only the safe path, category, rule,
impact, owner, and remediation boundary needed for review.
