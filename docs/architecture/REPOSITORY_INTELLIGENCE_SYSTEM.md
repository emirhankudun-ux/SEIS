# SEIS Repository Intelligence System

Date: 2026-06-19

The Repository Intelligence System is the deterministic scanner and evidence
layer for SEIS. It should understand repository structure without relying on an
LLM.

## Mission

Detect repository health, governance, documentation, validation, security, and
readiness signals from local files, Git metadata, and approved integrations.

## Detection Scope

| Category | Examples | First implementation mode |
| --- | --- | --- |
| Missing docs | `ARCHITECTURE.md`, `ROADMAP.md`, `CHANGELOG.md`, broken source-of-truth links. | Local filesystem scan |
| Broken links | Relative Markdown links to missing files. | Local Markdown scan |
| Risky files | `.env`, private keys, credential filenames, nested `.git`, generated folders. | Local path scan |
| Generated folders | `node_modules`, `.next`, `dist`, build caches, local archives. | Local path scan |
| Stale docs | Old branch model, outdated date, deprecated repository names. | Rule-based text scan |
| Orphaned files | Unlinked docs or reports outside index/navigation. | Local graph scan |
| Duplicate docs | Similar titles, repeated mission docs, old/current conflict. | Rule-based metadata scan first |
| Unmerged branches | Local branches ahead/behind. | Local Git scan |
| Open/closed PRs | PR status and recovery candidates. | Approved GitHub integration |
| Validation gaps | Missing scripts, failing checks, unrun checks. | Package/script inspection |
| Security gaps | Missing baseline, missing scans, risky tracked files. | Local scan and approved scanners |
| Public blockers | README/license/security/contributing/template/provenance gaps. | Local readiness checklist |

## Output Records

Repository intelligence should emit bounded, reviewable records:

```json
{
  "id": "repo-gap-001",
  "category": "missing_doc",
  "severity": "high",
  "path": "ARCHITECTURE.md",
  "status": "open",
  "evidence": "root architecture entry point not present",
  "recommended_action": "add root architecture index or document deferral",
  "requires_approval": false
}
```

## Evidence Rules

- Every finding needs a path, command, scan rule, or source file.
- Findings must never print secret values.
- Findings should distinguish tracked, untracked, ignored, generated, and
  external states.
- External state must be marked unknown unless an approved live integration was
  actually queried.
- LLM classifications are advisory and must not replace deterministic evidence.

## Initial Scan Commands

Safe local scanner foundations:

- `git status --short --branch`
- `git branch --all`
- `git log --oneline --decorate --max-count=100`
- `git ls-files`
- `git ls-files -d`
- `git ls-files --others --exclude-standard`
- path scans for risky filenames
- Markdown relative-link scans
- `package.json` script existence checks

Do not run destructive cleanup from scanners. Scanners report; humans approve.

## Public API Shape

Future app code should expose:

- `GET /repository/status`
- `GET /repository/findings`
- `GET /repository/docs`
- `GET /repository/validation`
- `GET /repository/security`
- `GET /repository/readiness`
- `GET /repository/evidence`

These can start as local static JSON files generated by scripts, then evolve
into service endpoints when there is a real app backend.

## Scanner Safety

Scanners must:

- Be read-only by default.
- Avoid network access unless explicitly configured.
- Avoid reading ignored large folders unless asked.
- Redact sensitive path details when necessary.
- Exit non-zero only for defined policy failures.
- Produce stable output for review and CI.

## First Implementation Milestone

Create a local `repository-intelligence` report generator that emits:

- Missing source-of-truth docs.
- Broken docs links.
- Deleted tracked files.
- Risky tracked filenames.
- Untracked and ignored nested repos.
- Missing referenced validation scripts.
- Current branch/ahead-behind state.
- Foundation/public/release readiness blockers.
