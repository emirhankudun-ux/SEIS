# ADR-0006: SEIS Five-Year Agency Orchestration Contract

## Status

Proposed

## Context

The owner selected every A/B/C option for the five-year development model:

- Roadmap and PR cycles.
- Real automation architecture.
- Active background agents when the platform permits.
- Official, installed, and candidate MCP policy tiers.
- Task-selected skills, full registry inventory, and per-round reselection.
- Source provenance, demo/UX adaptation, and Swift/Apple bridge as first milestone areas.
- Immutable zip sources, selected asset review, and manifest-level reference dumps.
- Kimi v1-v7 with v7 primary and older versions preserved as evolution evidence.
- Stitch as UX catalog, module idea pool, and read-only code reference.
- Small safe first PRs, then larger foundation packages only when split and reviewed.
- Demo-only AI Core, local-ready metadata, and cloud-ready keys-free metadata.
- Ledger/report, UI agent panel planning, and SEIS Brain context pack visibility.
- Existing checks, Swift checks when touched, and new provenance/orchestration checkers.
- Secret scan, MCP risk matrix, and zip license/size risk review.
- Decision-complete plan, PR-ready work breakdown, and 30-round swarm backlog.

SEIS already contains several authoritative sources for five-year planning, installed tools, plugin integration, MCP runtime, provider readiness, subagent policy, and source provenance. A new artifact should not duplicate or weaken those sources.

## Decision

Add a public-safe five-year agency orchestration contract as a thin index over existing SEIS registries and ledgers.

The contract defines:

- Five-year, 30-round, 50-step supervised execution.
- Owner-selected 30-round override while preserving the legacy 15-round ledger context.
- Truth boundaries that block live AI claims, unverified MCP install claims, credential storage, raw archive dumps, and uncontrolled subagent writes.
- Ten agency departments with assigned agents, tools, feature areas, and quality gates.
- Agent feature assignments and tool feature assignments.
- MCP activation, installed-use, candidate-use, and package-runner policy.
- 30-round run template and 50-step development ladder.

Add a direct Node checker to verify the contract shape, source links, safety booleans, round count, step count, agent coverage, tool coverage, MCP policy, and local path/secret guards.

## Consequences

Positive:

- The five-year objective becomes executable as repeatable supervised cycles.
- Future agents get one durable handoff without needing private conversation context.
- The contract supports agency-style coordination without claiming live autonomy.
- MCP, AI Core, and source provenance boundaries remain explicit.

Tradeoffs:

- The contract adds another governance artifact to maintain.
- Existing registries remain the source of truth; the contract must not drift from them.
- Package script wiring is intentionally deferred because the current `package.json` is already modified in the working tree.

## Alternatives Considered

Expanding the existing five-year subagent plan was rejected for this slice because the new owner decision set spans source provenance, MCP policy, tools, skills, UX, Swift, AI Core, SEIS Brain, security, and final output shape.

Creating a live scheduler was rejected because SEIS must not claim background autonomy unless the platform actually supports it and the run is verified.

Importing all archive contents into the repo was rejected because license, size, provenance, and public-safety review are required first.

## Follow-up

- Add package script wiring after the current dirty `package.json` ownership is clear.
- Expand the MCP permission risk matrix.
- Build the Stitch UX screen catalog from reviewed source summaries.
- Add a Swift model/manifest bridge only when it provides real Apple-first value.
- Use this contract to drive the next 30-round supervised run ledger.
