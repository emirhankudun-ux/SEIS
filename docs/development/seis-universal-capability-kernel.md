# SEIS Universal Capability Kernel

SEIS uses a generated capability kernel to keep broad development domains visible, scoped, and checkable.

## Command

```bash
npm run automation:universal-capability-kernel
npm run check:universal-capability-kernel
npm run check:seis-nonjs-kernel
npm run check:seis-platform-kernel
```

## Scope

The kernel covers engineering, full stack, data, design, development, AI, AI agents, MCP, skills, plugins, LLM routing, algorithms, flowcharts, mathematics, computer science, web, mobile, games, databases, Git, cloud, security, DevOps, testing, architecture, big data, NLP, computer vision, quantum programming, sustainable software, low-code/no-code platforms, UX/UI engineering, robotics, AI ethics, compiler design, requirements, agile delivery, SDLC, metrics, SRE, reverse engineering, refactoring, and formal methods.

## Outputs

- `content/development/seis-universal-capability-kernel.json`
- `reports/seis-universal-capability-kernel.json`
- `reports/seis-universal-capability-kernel.md`

## Non-JavaScript Surfaces

The aggressive kernel expansion is intentionally implemented outside JavaScript:

- Python package and unit tests for capability routing.
- Go package and tests for capability budget scoring.
- Rust gate model for typed readiness checks.
- SQL schema for domain, plugin, and quality-gate persistence.
- Rego policy for MCP/plugin/LLM activation guardrails.
- CUE contract for schema-level capability validation.
- SwiftPM package for Apple-native macOS policy and tests.
- SwiftUI Playground for inspectable Apple UI policy experiments.
- Objective-C bridge and AppleScript automation surface for Apple ecosystem integration.
- Windows multi-language surfaces across .NET, PowerShell, Batch, C++, Rust, Go, Python, Java, Kotlin, SQL, R, Lua, Ruby, and PHP.

## Rule

SEIS remains the task-facing AI agent. Local and remote LLMs, MCP servers, skills, and plugins are helpers behind scoped routing and must pass relevance, permission, credential, and user-approval gates before activation.
