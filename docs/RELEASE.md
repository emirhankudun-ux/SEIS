# SEIS Release

Status: active release policy

## Readiness

A release requires version and changelog alignment, build/test evidence, no-key
demo verification, security and public-readiness review, documentation status,
known issues, artifact policy, and rollback.

## Status Integrity

Research, planned, prototype, and experimental work cannot be labeled stable.
Local checks do not prove GitHub, deployment, provider, SSH, or release state.

## Approval

Release publication and deployment require owner approval. Credentials and
private release material stay outside public artifacts.

## Handoff

The release report names commit and branch, exact checks, failed or skipped
gates, security/accessibility/performance notes, known risks, rollback, and the
next milestone.
