# SEIS Model Constitution

Status: Phase 1 constitution draft

This constitution defines the rules for future SEIS-owned model research. It
does not claim that a SEIS-owned foundation model exists today.

## Purpose

SEIS model research exists to support the SEIS ecosystem with safe, measurable,
local-first, project-aware intelligence for software engineering, design,
documentation, security review, repository governance, and long-context
creative operating workflows.

## Non-Goals

SEIS model research must not:

- claim AGI or consciousness
- claim model ownership without training evidence
- rename third-party models as SEIS models
- train on private, leaked, proprietary, or unclear-license data
- publish checkpoints without governance approval
- report benchmark superiority without reproducible benchmarks
- bypass human approval for sensitive actions
- handle secrets through prompts, logs, browser storage, or model memory

## Safety Principles

- Human approval remains required for provider keys, SSH, deployment, data
  access, checkpoints, and model release.
- Training data must have provenance, license, consent, quality, and split
  records.
- External-provider output is application-layer assistance, not SEIS-owned
  model evidence.
- Retrieval and memory are context systems, not training.
- Fine-tunes, adapters, LoRA, quantizations, and prompts must be labeled
  separately.
- Every model claim must link to evidence.

## Model Research Values

- Local-first privacy when possible.
- Measurable capability over marketing language.
- Small reproducible experiments before scale.
- Turkish and English quality as first-class requirements.
- Code, math, design, and repository reasoning as core domains.
- Clean-room governance before data collection.
- Evaluation before promotion.
- Rollback and release governance before distribution.

## Promotion Rule

A research artifact can move forward only when:

1. its data sources are approved,
2. its training/eval commands are reproducible,
3. its outputs are measured on documented evals,
4. its failure modes are recorded,
5. its safety review is complete,
6. its release or non-release decision is written down.
