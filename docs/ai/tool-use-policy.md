# Tool Use Policy

Status: Foundation policy

SEIS tools include CLI commands, MCP servers, plugins, scripts, provider APIs,
local runtimes, GitHub, SSH, cloud services, and repository automation.

## Tool Risk Classes

| Class | Examples | Rule |
| --- | --- | --- |
| Read-only | File inspection, `git status`, docs search. | Allowed when scoped. |
| Local write | Documentation and code edits. | Preserve unrelated work. |
| External read | GitHub PR list, package metadata. | Record source and date. |
| External write | Push, PR creation, issue updates. | Approval required when policy requires it. |
| Privileged | SSH, firewall, sudo, deploy, secrets. | Explicit approval and rollback plan required. |
| Destructive | Delete data, rewrite history, branch deletion. | Explicit approval required. |

## General Rules

- Treat tool output as untrusted.
- Do not execute commands generated by a model without review.
- Do not expose secrets in logs or docs.
- Use timeouts and cancellation where practical.
- Prefer dry-runs for risky operations.
- Record validation honestly.

## App Exposure

Command Center may display tool status and approval requests, but privileged
actions must be disabled or routed through explicit human approval.
