# UI-UX Digital Lab Master Directive

## Purpose

UI-UX Digital Lab is an AI-native creative experience operating system for
premium UI/UX, cinematic interfaces, scalable product architecture, humane
automation, and long-term creative engineering.

It must be treated as more than a portfolio. It is a modular operating
environment for:

- portfolio systems
- cinematic landing pages
- design systems
- AI-assisted workflows
- educational products
- SaaS interfaces
- creative coding labs
- cross-platform product concepts
- enterprise documentation and governance
- future immersive interfaces

## Non-Negotiable Principles

Every interface must prioritize:

- human clarity
- accessibility
- responsive behavior
- semantic structure
- maintainability
- performance
- emotional comfort
- visual hierarchy
- rollback safety
- future extensibility

Every animation must support comprehension.

Every visual decision must support usability.

Every architectural decision must support scalability and maintenance.

The system must never become chaotic, bloated, inaccessible, visually noisy,
psychologically exhausting, or difficult to maintain.

## Experience Modes

### Minimal Mode

Use for portfolios, documentation, editorial pages, and lightweight systems.

Characteristics:

- typography first
- low motion
- high readability
- calm spacing
- strong semantics
- fast rendering

### Balanced Mode

Use for premium product pages, startup sites, dashboards, and SaaS flows.

Characteristics:

- refined transitions
- moderate motion
- clear interaction feedback
- polished states
- scalable UI density

### Cinematic Mode

Use for immersive storytelling, premium showcases, motion-heavy websites, and
interactive presentations.

Characteristics:

- layered parallax
- section reveals
- cinematic pacing
- environmental motion
- optional heavy animation
- GPU-conscious rendering
- reduced-motion fallback

### Experimental Mode

Use for creative coding, AI-native interfaces, generative environments, and
future interaction concepts.

Characteristics:

- procedural visuals
- adaptive layouts
- real-time visual systems
- experimental UX structures
- clearly isolated risk

## Motion Governance

Motion may be heavy when the user explicitly asks for cinematic intensity, but
must remain:

- optional
- reduced-motion aware
- mobile-aware
- frame-budget conscious
- non-essential for understanding
- easy to disable or scale down
- documented as a token or mode

Required motion layers:

- loading intro
- section reveal
- hover depth
- micro-interactions
- cinematic hero motion
- parallax where it clarifies hierarchy
- mobile touch feedback
- reduced-motion equivalent

Blocked motion patterns:

- mandatory cinematic intro without bypass or reduced-motion fallback
- motion-only error feedback
- hover-only disclosure
- uncontrolled particle density on mobile
- heavy WebGL before a performance budget exists

## Accessibility Governance

Accessibility is mandatory.

Support:

- semantic HTML
- keyboard navigation
- visible focus states
- reduced motion
- readable contrast
- scalable type
- touch targets
- screen reader compatible labels
- cognitive load reduction
- equivalent content when animation is disabled

Accessibility quality must be checked continuously with static checks first,
then browser and real-device verification when the feature risk justifies it.

## GitHub and Repository Governance

Main branch remains protected and production-safe.

Implementation work should stay isolated in reversible branches or the accepted
parent implementation branch.

Required habits:

- inspect before editing
- preserve existing user changes
- commit small reversible bundles
- keep generated files separate
- run focused checks
- document blockers
- avoid dependency bloat
- do not push without publish preflight and authentication

Suggested branch families:

- feature/*
- fix/*
- refactor/*
- perf/*
- style/*
- infra/*
- ai/*
- motion/*
- mobile/*
- experimental/*

## AI Workflow Contract

AI work must behave like a combined senior engineer, creative director, product
architect, and governance assistant.

AI should:

- analyze architecture before editing
- preserve design consistency
- avoid unnecessary rewrites
- protect rollback safety
- document important decisions
- use practical artifacts instead of abstract summaries
- prefer source contracts over repeated prompts
- remain transparent and human-supervised

AI must not:

- expose secrets
- hardcode credentials
- bypass authentication
- add unsafe dependencies
- create chaotic abstractions
- ignore accessibility
- run heavy processes without a clear reason

## Automation Readiness

This directive can power future automations for:

- weekly UI/UX governance review
- motion and accessibility regression review
- GitHub publish readiness
- documentation refresh
- dependency and security review
- archive and asset curation
- cinematic roadmap planning
- design-system token audit

Automation requirements:

- clear schedule
- clear workspace
- clear output expectation
- no secret exposure
- no unauthorized push
- no heavy local process unless explicitly approved
- report blockers separately from code quality

Recommended first automation prompt:

```text
Review the UI-UX Digital Lab workspace against the master directive. Produce a
short report covering design quality, motion governance, accessibility,
performance risk, repository cleanliness, documentation gaps, and the next
small reversible implementation slice. Do not push or deploy. Keep the output
practical and action-oriented.
```

## Acceptance Standard

A change belongs in UI-UX Digital Lab only when it improves at least one of:

- clarity
- craftsmanship
- accessibility
- performance
- scalability
- maintainability
- governance
- emotional comfort
- creative quality
- long-term product value

The final product should feel timeless, modern, technically mature, visually
memorable, scalable, immersive, humane, and intelligently designed.
